# HookWars: правила разработки

Общаться с пользователем по-русски, объяснять изменения понятно начинающему разработчику.

## Перед изменениями

- Изучить связанные скрипты, их вызовы, события и сериализованные ссылки в сценах и префабах. Учитывать порядок Awake/Start/Update/LateUpdate и DefaultExecutionOrder.
- Прочитать `docs/current-state.md` и применимые спецификации в `docs/specs/`. Отличать фактическое поведение от желаемого.
- Делать небольшие законченные задачи с понятным результатом. Не менять игровые правила, баланс, цены, награды и параметры без соответствующего задания.

## Сохранность проекта

- Сохранять существующие `.meta` и GUID. Переносить ассет вместе с `.meta`; не пересоздавать метаданные существующих ассетов.
- Сохранять ссылки на компоненты, fileID, ссылки сцен и префабов. Перед переименованием сериализованных полей проверить сохранение значений и совместимость.
- Не откатывать чужие изменения. Перед коммитом проверять весь состав, исключать секреты и генерируемые файлы.
- В Git хранить Assets со всеми исходными `.meta`, Packages, ProjectSettings и документацию. Не сканировать Library, Temp, Logs и другие генерируемые каталоги при изучении проекта.
- Не удалять `ignore.conf` и данные Unity Version Control. Не публиковать проект и не отправлять коммиты в remote без задания.

## Проверки и документация

- Выполнять доступные и соразмерные задаче проверки: diff, состав Git, исходники, GUID и сериализованные ссылки; для поведения — доступные тесты и Unity Play Mode.
- В отчёте явно различать чтение/проверку исходников, компиляцию, автоматические тесты и реальный запуск Unity. Не заявлять работоспособность по одному просмотру кода.
- Для этого проекта использовать Unity 6000.6.6f1, сверяясь с ProjectSettings/ProjectVersion.txt. Наличие .NET SDK само по себе не подтверждает сборку Unity.
- Хранить игровые спецификации в `docs/specs/`. При изменении поведения обновлять применимую спецификацию и `docs/current-state.md`, указывать ограничения проверок и известные проблемы.
- Новую экономику реализовывать только после получения соответствующей спецификации.
