## Причина качения и правила анимации

Source BodyRoll/pivot находятся в (0,1.04,0), но тело — эллипсоид
1.02/1.04/.87 м. Runtime AlignGround двигал весь RigVisual по текущему
BakeMesh и повторно применял служебный импортный scale=100. Производный
CenteredBody.asset строится один раз в координатах BodyRoll через bindpose,
приводит радиус к 1.04 м, сохраняя UV/веса/индексы. FBX не изменён.
Scale .48 даёт радиус .4992 м; постоянный центр .5142 м, низ .015 м.
Нет покадрового BakeMesh/AABB-подъёма. Голова и оружие вне BodyRoll.

Roll выбирается из фактической добровольной скорости, переведённой в
локальные оси взгляда; N=+Z, E=+X. Частота speed/(2πradius), единая фаза,
без процедурного перезаписывания BodyRoll/смешивания противоположных
вращений. Остановка сохраняет достигнутую ориентацию, захват/телепорт/
возрождение исключены. Axe/Hook — отдельные маски ветвей; игровой код
единолично определяет попадание/выпуск. Player axe speed=1.142857,
удар=.35с; Enemy speed=1, удар=.4с. Cast=.6с, release=7/30с,
зафиксированное направление. Смерть/захват отменяют прошлые события.

Цех работает при реальной очереди RawKg, лавка открыта при продукции/
продаже с удержанием .25с между тиками. Farm_Loop декоративный, Wall_Ambient
не даёт игровых эффектов. Walk животных получает только добровольную
скорость; упор останавливает шаг, после .22с Graze; захват замораживает
анимацию. Туши статичны и не имеют Animator/боевых скриптов.

## Цепь и нагрузка

Реальные динамические звенья HookWarsChain, без PhysicalHookChain мясника.
Кинематические крепления руки/крюка/отскока, независимые физические участки,
пул выдачи у руки и обратного втягивания. Существующие тела сохраняют
позиции/скорости; число меняется без Rebuild всего объекта. При возврате
направляющие снимаются после прохождения логического изгиба.

N=ceil(выданная физическая длина/(.168×linkScale)); частичное последнее
звено имеет скользящее крепление. Толщина независима от шага, maximumLinks
не ограничивает дальность. 3D-высота сокета/провисание учтены в физической
длине, но не в игровых попаданиях; HookAbility единолично ограничивает
логическую длину. Активными dynamic poses владеет только PhysX.

Изолированная LocalPhysicsScene3D, слои 24/25 и прокси земли/гор/зданий.
По одному envelope CapsuleCollider на полную объёмную модель кольца вместо
16 проволочных коллайдеров. Между звеньями/цепями/владельцем/грузом контактов
нет. Прокси следуют строительству/разрушению/изменению поля, без урона.

Финальная симуляция выполняется после поз рук/крюка в LateUpdate,
без Rigidbody interpolation. Подшаг fixedDeltaTime/16 или мельче при
перемещении креплений; 128 solver iterations адресно на звено, projection off.
Это исправило рассогласование предыдущего FixedUpdate с текущими визуалами.

Последний прогон: **345 динамических звеньев, 345 коллайдеров**, всего
357 Rigidbody с пулом/креплениями/участками. 5513 активных кадров симуляции:
**среднее 1.0849 мс, пик 49.5608 мс** на всю локальную симуляцию кадра.
Editor-прогон включает выдачу объектов/снимки; источник пика отдельно не
изолирован. Это не доказательство стабильных 60 FPS в release. Максимальная
ошибка всех соединений (включая руку) **.0652 м**, предыдущий прогон .1973 м;
на контрольном длинном кадре <.05 м. Тест ограничивает полный сценарий .35 м.
[Необработанные измерения](008-chain-profile.txt).

## Windows development build

MainMenu, Arena25D. Windows Build Support установлен. Настоящий BuildPipeline
создал `Builds/WindowsDevelopment/HookWars.exe`, **Succeeded, 0 ошибок**,
292004012 байт, 11.72с в последней сборке. [Build report](008-windows-build.txt).
511 предупреждений: штатные shader warnings пакета com.unity.ai.inference
(Sentis) и отсутствие необязательной конфигурации пакета com.unity.pipeline;
[точные сообщения](008-windows-build-warnings.txt). Демоассеты к игре не добавлялись.

Первый exe действительно запущен с D3D11 и тестовым аргументом
`-hookwars-smoke <каталог отчёта>`. Меню появилось, первые три проверки
прошли; запись PlayerPrefs вызвала `PlayerPrefsException: Could not store
preference value`, затем тест завершился своим таймаутом. Ошибка исправлена:
настройка теперь в bank-depth.txt, в Editor повторно прошли 102 проверки.
Исправленная версия пересобрана. **Повторный запуск exe был дважды отклонён
средой: CreateProcessAsUserW failed: 5 (Отказано в доступе). Успешный полный
standalone-прогон не выполнен.** Запуск исправленной сборки остаётся ручным.
Не обходились ограничения доступа и не запрашивался второй Editor.

Для самостоятельной проверки открыть exe обычным способом: меню → 4м →
Esc/меню →16м →меню →20м, проверить чистые ресурсы и бой. При необходимости
development-only автоматизация включается явным аргументом
`-hookwars-smoke C:/Users/iliak.ILIAPC/HookWars/Temp/WindowsSmokeManual`:
три цикла, реальные screenshots и result.txt, автоматический выход.
Без аргумента никакой тестовый runner не создаётся.

## Оставшиеся проверки и ограничения

- Ручной продолжительный матч мышью/клавиатурой и исправленный Windows player.
- Производительность release, большая популяция и более двух активных цепей.
- Остаточная ошибка итерационного решателя цепи; за пределом .35м тест падает,
  игровая длина при этом не расширяется. Пики CPU требуют профилирования.
- Настольный UI: при очень узком окне поле уменьшается, адаптивная мобильная
  раскладка не реализована. Горные границы пока простые 3D-блоки с прокси.
- Отдельного клипа смерти в исходнике нет; используется статичное состояние.
- Ферма/лавка не содержат экономического ИИ противника. Прогресс между боями
  намеренно не сохраняется, только выбранная глубина.

Требования к будущим моделям, координаты, маски, опора и безопасные туши
зафиксированы в спецификации 008. Исходные .blend остаются вне Assets.
